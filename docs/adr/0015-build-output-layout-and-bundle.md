# ADR-0015: Build-output layout and bundle trimming

- **Status:** Accepted
- **Decided:** 2026-09-14
- **Implemented:** 2026-09-14 (verified: `typecheck` clean; **1582** unit cases pass (incl. 9 prune + 10 vendor-chunk + 4 afterAllArtifactBuild hook + 2 packaging-config cases); `npm run build` emits `dist/electron`, prunes 38 redundant fonts and is chunk-size-warning-free; all 20 built `@font-face` blocks list `.woff2` first; `dist/renderer/index.html` no longer `modulepreload`s mermaid / franc / katex / highlight.js; `npm run dist` yields an 11.8 MB `app.asar` (was 105.8 MB) and a 149.2 MB zip (was 175.2 MB), and the packaged `release/win-unpacked/MarkFlow.exe` was **launched** — title, preload bridge, KaTeX (2 nodes) and mermaid (1 SVG) all render with zero console/page errors; e2e suite green. Size figures in this ADR were measured against `release/markflow-2.2.0-win.zip`, `release/win-unpacked` and the `app.asar` header, not estimated.)

## Context

Two recurring pain points around the build:

1. **Confusing output locations.** `npm run dist` produced its real artifact in `release/`, while `dist/` (renderer) and `dist-electron/` (electron main + preload) looked like the product but were only intermediate bundler output. A third, redundant `out/` directory was a stale `tsconfig.node.json` `tsc` emit. Developers repeatedly hunted for the packaged app in the wrong folder.
2. **Payload size / startup.** Measured on Windows (Electron 44.3.0, after `npm run dist`): the shipped `release/markflow-2.2.0-win.zip` is **175 MB** and unpacks to **473 MB** (`release/win-unpacked`). Two independent contributors:
   - **Electron/Chromium runtime — 367 MB** (`node_modules/electron/dist`: `electron.exe` alone is 235 MB, plus `locales` 48 MB, `dxcompiler.dll` 25 MB, `LICENSES.chromium.html` 20 MB, …). This is the unavoidable floor for any Electron app. (An earlier draft of this ADR said "~180 MB" — that number was wrong.)
   - **App payload — `app.asar` was 106 MB**, itself only **11.8 MB of real app** (`dist/renderer` 10.6 MB + `dist/electron` 1.2 MB) plus **91.8 MB of `node_modules`** — production dependencies Vite had _already_ bundled into `dist/` and electron-builder then re-packed into the asar. That duplication was the single largest win and is now removed (see "Bundle trimming"), bringing the asar to **11.8 MB** and the zip to **149 MB**.
     The trimming below targets the app payload: KaTeX shipped every glyph in `.ttf` + `.woff` + `.woff2` (60 files in `katex/dist/fonts`, of which 59 reach the bundle), and `mermaid` (~2.5 MB) was eagerly imported on the renderer's main thread.

## Decision

### Layout (reorganization)

- **Bundler outputs live under one `dist/` root:**
  - `dist/renderer/` — Vite renderer build (unchanged location).
  - `dist/electron/` — electron **main** (`index.js`) + **preload** (`preload.cjs`), moved here from `dist-electron/` (both builds set `emptyOutDir: false` so they don't wipe each other).
- **`release/` remains the packaged-app output** (electron-builder `directories.output`). It is the single source of truth for "the shipped app"; the electron-builder **`afterAllArtifactBuild`** hook (`scripts/after-all-artifact-build.mjs`) prints the artifact paths when packaging finishes, so no extra `&& node …` step is needed on the `dist` scripts.
- **Delete the stale `out/`** tsc emit (gitignored, redundant with `vite-plugin-electron`). `tsconfig.node.json` is still used for `--noEmit` typecheck, so it does not regenerate during normal flows.
- Updated everywhere `dist-electron` was referenced: `package.json` `main`, `electron-builder.json5` `files`, `eslint.config.mjs` ignores, the four linter ignores (`.prettierignore`, `.secretlintignore`, `.stylelintignore`, `.markdownlint-cli2.jsonc`), `.gitignore`, `.github/workflows/ci.yml`, `playwright.config.ts`, `electron/main/index.ts` + `electron/main/lib/app-paths.ts` (`MAIN_DIST`), e2e `launch.ts` + `global-setup.ts`, and README/QUICKSTART.

### Bundle trimming (within Electron)

- **Exclude `node_modules` from `app.asar`** — `!node_modules` + `!node_modules/**/*` in the `electron-builder.json5` `files` list. The single largest win of this ADR. Both builds are **fully bundled**: `dist/electron/index.js` has no bare `require()` except Node builtins (`buffer`, `stream`, `string_decoder`) and contains chokidar / iconv-lite / jschardet-ultra, and the renderer is a self-contained set of chunks — so the 91.8 MB of production dependencies electron-builder re-packed into the asar (mermaid 41 MB, cytoscape-fcose 9 MB, elkjs 8 MB, highlight.js 5 MB, katex 4 MB, …) was pure duplication. Measured: `app.asar` **105.8 MB → 11.8 MB**, `release/markflow-2.2.0-win.zip` **175.2 MB → 149.2 MB**, unpacked **473.1 MB → 379.1 MB**. Verified by launching the packaged `release/win-unpacked/MarkFlow.exe`: window title, preload bridge, a pasted document, KaTeX (2 nodes) and mermaid (1 SVG) all work with **zero** console/page errors. Guarded by `scripts/packaging.test.ts`.
- **Lazy-load the parse pipeline's main-thread fallback** — `parseClient.ts` keeps only a **type-only** import of `markdownPipeline` and `fallbackParse` now does `await import('../lib/markdownPipeline')`. This takes `vendor-katex` (546 kB) and `vendor-highlight` (921 kB) out of the renderer's static import graph, so they are no longer `modulepreload`ed — **~1.47 MB off first paint** (verified: neither chunk appears in `dist/renderer/index.html`). The pipeline still calls `katex`/`highlight.js` **synchronously** inside `md.render()`; that is unchanged, and it is why they cannot be lazy-loaded _there_. They now simply load only when the Worker is unavailable. **This change alone was not enough** — see the vendor-chunk correction below.
- **Packaging options** (`electron-builder.json5`): `compression: 'maximum'` (a **root-level** option in electron-builder 26 — it applies to the packaged archive, e.g. the `zip`), plus `!**/*.map` in `files` (defense; Vite emits no sourcemaps by default). **Correction:** an earlier attempt used `asar: { compression: 'maximum' }`, which is **invalid** in electron-builder 26 — `asar` is a boolean (default `true`) and `AsarOptions` only accepts `ordering`/`smartUnpack` (`additionalProperties: false`), so it hard-failed packaging. The app-source packing is unchanged (asar is on by default); the payload shrink comes from the font prune below.
- **Font prune** — a Vite plugin (`pruneKaTeXFallbacks` in `scripts/prune-fonts.ts`, registered in `vite.config.ts`): in the `generateBundle` hook, drop `.ttf`/`.woff`/`.eot`/`.otf` for any KaTeX font family that also emits a `.woff2`, so they are never written to `dist/renderer`. Runs for **any** `vite build` (CI, direct invocation), not just the npm script. Conservative by design — a family with **no** `.woff2` asset keeps its fallback formats, so no glyph ever breaks. In practice exactly one family is affected: `KaTeX_Size3-Regular`, whose 3.6 kB `.woff2` falls **under Vite's default `assetsInlineLimit` (4096 B)** and is therefore inlined into the CSS as a `data:` URI (it is _not_ KaTeX that inlines it), so no `.woff2` file reaches the bundle and Size3's `.woff`/`.ttf` survive. Result: 59 → 21 font files (38 removed). The built CSS still lists the removed files as later `src` fallbacks; this was verified inert — all **20** `@font-face` blocks in `dist/renderer/assets/vendor-katex-*.css` list a working `.woff2` source **first** (Size3's being the `data:` URI), so Chromium/Electron selects it and never requests the pruned fallbacks. **Caveat:** the Size3 exemption is an artifact of `assetsInlineLimit`, not a KaTeX property; if that limit or the font's size changes, which families are exempt flips. The prune stays safe either way (it only removes a format when a `.woff2` for that family is actually emitted), but the resulting file count will move.
- **Lazy-load `mermaid`** in `MarkdownPreview.tsx` via dynamic `import('mermaid')`, cached after first use. It is no longer in the initial preview chunk (~2.5 MB off the first paint).
- **Lazy-load `franc`** only when exporting/printing (`lang.ts` → `detectContentLang` now async).
- **Vendor chunk splitting** — the renderer's `manualChunks` policy lives in `scripts/vendor-chunks.ts` (`vendorChunkFor`, unit-tested). A few families (mermaid, katex/mathjax, the CodeMirror/lezer editor stack, the radix-ui/tanstack UI stack, d3) get grouped chunks; EVERY other `node_modules` package gets its own `vendor-<pkg>` chunk. Previously a single catch-all `vendor` chunk aggregated enough libraries — `highlight.js`, `lodash-es`, and mermaid's transitive deps whose package names lack "mermaid" (`dagre-d3-es`, `chevrotain`, `khroma`, `es-toolkit`, …) — to exceed `chunkSizeWarningLimit` (3000 kB) and emit a "larger than 3000 kB" warning on every build. Per-package splitting removes the aggregation, so the build is warning-free. Chunk names do not affect eager/lazy loading (Rollup decides that from the import graph), so this is purely an output-size / caching change.
  - **Correction — the policy must apply to SCRIPT modules only.** It originally matched on the bare `katex` / `highlight.js` substrings, which also matched the **statically imported stylesheets** (`main.tsx` imports `katex/dist/katex.min.css` and `highlight.js/styles/github.css`; `export.ts` imports the katex CSS with `?raw`). Those CSS modules were bundled into the same chunks as the 546 kB / 921 kB libraries, so the chunks stayed in the entry's **static** graph and Vite kept emitting them as `modulepreload` links — even after the fallback became dynamic. `vendorChunkFor` now skips every id that is not a script (extension allowlist, query string stripped first), so stylesheets fall through to Vite's default and can never drag a library into the eager graph. Side effect: the renderer's CSS is emitted as a single `index-*.css` instead of three files. Locked in by `scripts/vendor-chunks.test.ts`.

### Tool-native hooks instead of npm-script chaining

The post-build steps are expressed through each tool's own extension point rather than `npm` script chaining (`vite build && node …`): the font prune is a Vite plugin (`generateBundle`) and the output announcement is an electron-builder `afterAllArtifactBuild` hook. Both therefore run for **any** invocation of the tool (CI, direct `vite build`/`electron-builder`), not only when called through the npm script, and the npm scripts stay clean (`build: "vite build"`, `dist: "npm run build && electron-builder"`).

### Explicitly NOT changed

- **Lazy-loading `katex` / `highlight.js` INSIDE the render pipeline** — still rejected. They are called **synchronously** by markdown-it's `highlight` callback and by `texmath` during `md.render()`, so `import()`-ing them would require making `md.render()` async, i.e. rewriting the render pipeline. What changed is only _when the pipeline itself_ is loaded (the Worker fallback is now dynamic — see "Bundle trimming"), not the sync constraint inside it.
- **Trimming `node_modules` from `app.asar`** — no longer "not done": it is implemented (see "Bundle trimming"). The caveat still stands as an operational rule: if a runtime dependency is ever needed again, this exclusion must be replaced by a per-package allow-list, and the change can only be signed off by packaging **and launching** `release/win-unpacked/MarkFlow.exe`.
- **Switching runtimes to Tauri** was considered as the only way to dramatically shrink the Chromium-based exe, but it is a ground-up Rust rewrite and is out of scope for an "optimize in place" task. Recorded here as a future spike, not adopted.

## Consequences

- **Positive:** one obvious `dist/` root for builds, `release/` unambiguously the shipped app, build prints where to find it.
- **Positive:** `app.asar` **105.8 MB → 11.8 MB** (91.8 MB of duplicated `node_modules` + 38 redundant KaTeX font files gone); shipped zip **175.2 MB → 149.2 MB**; unpacked **473.1 MB → 379.1 MB**.
- **Positive:** the renderer's first paint no longer pulls mermaid (2.6 MB), franc (0.24 MB), katex (0.55 MB) or highlight.js (0.92 MB) — all four are dynamic chunks now.
- **Positive:** font pruning, mermaid/franc lazy-load and the vendor-chunk policy are low-risk and test-covered (`scripts/prune-fonts.test.ts`, `scripts/vendor-chunks.test.ts`, `MarkdownPreview.test.tsx`), and the pruning's main runtime risk — that a glyph or a formula stops rendering — is guarded end-to-end by `e2e/specs/katex-preview.e2e.spec.ts`.
- **Positive:** every renderer chunk now stays under `chunkSizeWarningLimit`, so `npm run build` is warning-free; the per-package policy also absorbs future dependencies without revisiting `vite.config.ts`.
- **Negative / trade-off:** the **367 MB** Electron runtime is accepted as a hard floor, so even with the app payload trimmed to 11.8 MB the shipped artifact is still 149 MB zip / 379 MB unpacked — the app payload was never the dominant term. True _order-of-magnitude_ weight reduction would require leaving Electron.
- **Negative / trade-off:** excluding `node_modules` leaves the packaged app with **no** dependency source on disk. Anything that needs a runtime dependency (a native module, a package read at runtime rather than bundled) will now fail **only in the packaged build** while working fine in dev. Mitigation: `scripts/packaging.test.ts` locks the exclusion, and `npm run dist` + launching `release/win-unpacked/MarkFlow.exe` is the required sign-off for any dependency change.
- **Negative / trade-off:** the renderer emits one chunk per `node_modules` package, so the asset count is higher. That is a deliberate caching/size trade-off (each vendor caches independently); chunk names do not change load semantics.
- **Negative / trade-off:** `dist/electron` and `dist/renderer` now share the `dist/` ignore in eslint; the deleted `out/` folder will not return during normal dev (typecheck uses `--noEmit`).
